# Architecture and Extensibility Guide


## Start here

Prepare selected resources explicitly, then run inference offline. Conversation processes completed utterances through capture/VAD → recognition → translation → optional speech output; Text calls the same translation contract without the speech stages. There is no cloud or hidden backend fallback.

| Area | Responsibility and starting point |
| --- | --- |
| `app` | Compose screens, settings and selected resource ownership: `runtime/AppRuntime.kt`, `runtime/RuntimeOwner.kt`. |
| `core` | Contracts and bounded session state: `ConversationPipeline.kt`, `TranslationEngine.kt`. `SpeechToTextPipeline.kt` is a separate evaluation/library consumer, not the Text screen. |
| `engine-mlkit` | Explicit-direction translation clients and actual Google Task lifetimes, including work that outlives coroutine cancellation. |
| `engine-tencent` | Shared pinned GGUF preparation and owner-scoped embedded CPU llama.cpp JNI inference. |
| `speech-models` | Shared strict catalog parsing, verified model storage, download/extraction and selected capture/output projection. |
| `engine-sherpa` | Native capture/VAD, joint selected-pair Whisper, retained evaluator ASR and Piper profiles/handles. |

Pipelines own mutable session queues; runtime owners serialize configuration changes and await teardown before replacement; adapters own actual SDK/JNI work. Cancelling a coroutine is not resource-release evidence. Only configuration and installed resources persist—not conversation history. Native content logging remains an unresolved privacy limitation.

For a focused change, start with the recipes below: [text language](#1-add-a-text-language), [speech model or adapter](#2-add-a-speech-model-or-adapter), [translation provider](#3-add-a-translation-provider), or [persistent setting](#4-add-or-migrate-a-persistent-setting). Read [CONTRIBUTING](../CONTRIBUTING.md) for build checks and [verification](testing/verify-translator.md) for platform evidence. Detailed platform protocols and dated results are reference material, not onboarding prerequisites.

[APP_VISION.md](APP_VISION.md) defines the product direction; [README.md](../README.md) describes the current state. This guide covers existing architecture, contracts and extension points.

## Current Implementation


- `core` supplies language/configuration types and speech/translation contracts. `app` owns settings, UI, runtime construction and lifecycle coordination. `engine-mlkit` and `engine-tencent` are real registered translation providers; one `translationEngineId` controls both modes. First-launch choice commits atomically with `translationSetupComplete` before either route mounts. Sherpa owns compiled native profiles, while `speech-models` owns the shared verified speech store.
- `ConversationRuntimeOwner` constructs `ConversationPipeline`. The current contracts process completed `SpeechSegment`/utterance inputs: `ConversationRecognitionEngine.recognize(segment)`, `TranslationEngine.translate(pair, text)`, and `ConversationSpeechOutput.speak(language, text, onPlaybackStarted)`. The recognition result is either a directed `RecognizedUtterance` or retained text in `UndeterminedLanguage`; the pair-level contract does not mandate a detector before ASR. Online ASR adapter families do not by themselves establish an incremental end-to-end conversation API.
- `AppRuntime` constructs common production Sherpa capture/VAD, exactly one selected Android or Whisper recognizer and exactly one Android/Piper output adapter. Recognition always requires real readiness; output readiness and voice resources are required only when speech output is enabled. Every acquired stage still requires awaitable release. Start always requires capture, recognition and translation resources.
- `LanguageCatalog` contains 17 languages: `en,vi,es,id,it,zh,ko,de,pl,pt,ru,th,tr,fr,hi,ja,nl`. `AndroidSpeechLocales` is the single ASR/TTS platform mapping; Dutch uses `nl-NL`, while ML Kit uses `nl`. Chinese is `cmn-Hans-CN` recognition and `zh-Hans-CN` output, with Mainland CN/Hans-or-unspecified-script voice eligibility and no Hant/TW/HK/MO substitution. ML Kit still uses base IDs. Catalog support and actual installed service resources are separate.
- Immutable `AppSettings.languagePair` is the only ordered pair on both main screens. Basic Settings contains the shared translator, interface language and voice speed; recognition/service, output, end-of-speech silence and Reset are advanced. `ConversationSessionConfig` derives both directions; Whisper selects one shared ASR ID and System no native recognition IDs. Piper alone selects native TTS IDs and retains RU/EN coverage; voice resolution is deferred while output is disabled. Wider Whisper ASR does not install voices. VAD is fixed internally, without a model selector. System resources cannot be represented by fictional native model-store rows. An uncovered voice pair may remain valid for Text or silent Conversation when recognition and translation support it.

### Translation Method Is Not Translation Quality

`TranslationCapability` currently has four states:

| State | Existing meaning |
| --- | --- |
| `Direct` | One source-to-target model invocation, with provider-specific routing evidence. |
| `Pivot(via)` | Translation through the stated intermediate language. |
| `Unsupported` | The provider does not support the pair. |
| `Unknown` | Directness has not been verified. |

`Direct` and `Pivot` describe method, not a quality verdict. `Unknown` is neither SDK-unsupported nor evidence of poor translation. SDK support, directness evidence, semantic quality, offline operation, speech coverage, and device qualification must remain separate facts.

ML Kit's [translation documentation](https://developers.google.com/ml-kit/language/translation) describes English as the intermediary for non-English pairs; its [supported language codes](https://developers.google.com/ml-kit/language/translation/translation-language-support) are a separate SDK-support boundary. `MlKitTranslationEngine.capability(pair)` first checks `supportedLanguages`, reports non-English pairs as `Pivot(en)`, and reports English partners as `Direct` only when they appear in `verifiedEnglishPartners`; other SDK-supported English partners report `Unknown`.

Dutch is already in the SDK-supported codes: English↔Dutch remains executable `Unknown` without verified directness evidence, while Russian↔Dutch is SDK-managed `Pivot(en)`. The catalog addition does not change `verifiedEnglishPartners`, certify translation quality or add Sherpa/Piper resources. Whisper supplies selected-pair Dutch recognition independently of Android packs, but System output still requires genuinely installed offline voices.

**Executable support is coordinated across every boundary.** Core `requireSupported()`, `SettingsValidator`, `TranslationEngineRegistry.create()`, and ML Kit selected/prepare/translate accept `Direct`, `Pivot`, and SDK-supported `Unknown`, rejecting genuine `Unsupported`. `Unknown` remains unknown directness, not unsupported or manufactured `Direct`.

The application calls ML Kit once with the original source/target pair. It neither performs manual double translation nor edits inputs to hide failures. Prepare queries/deduplicates only selected non-English SDK model packs; translate never downloads. Selected-pair bounds, cancellation, in-flight SDK leases and error reporting remain. Catalog/UI breadth does not justify a duplicated permanent42-case execution matrix: preserve distinct contract/consumer boundaries and qualify representative real directions separately.

Tencent reports Direct for every distinct pair in the current 17-language catalog, including Dutch: this describes one multilingual model invocation, not semantic qualification. The historical 240-direction evidence below covers the earlier 16-language catalog, not the added Dutch directions. Its target instruction requests Simplified Chinese for `zh`. One process-shared `TencentArtifactPreparation` owns private no-backup weights and an installation lock, not a global inference context. Each selected `TencentTranslationEngine` owns one serialized native executor/model/context and joins cancellation before slot reuse or release. Prepare explicitly installs/attests the exact artifact, loads it and runs bounded neutral warmup; a new owner needs local Prepare even when weights are already present. Translate never downloads, initializes missing weights or falls back.

`TranslationEngine.preparation` is a provider-neutral StateFlow of checking/missing/downloading/verifying/loading/ready/failed, nullable Long byte counts and typed `TranslationFailure`. READY includes initialization, not just a completed download. ML Kit reports indeterminate real SDK preparation. Text and Conversation observe the actual owner's state; conversation readiness still requires all selected speech stages. Typed missing/corrupt/storage/load/memory/context/token/output/Unicode failures are localized without surfacing native diagnostic strings or partial successful text. Coroutine cancellation stays cancellation.

Tencent downloads use explicit validated Wi-Fi-bound HTTPS connections, bounded official-host redirects, a 30-minute total deadline, 60-second IO inactivity bound, 64-KiB buffers, exact byte/SHA verification and atomic same-directory publication. Cold attestation caches only the unchanged file identity; corrupt weights require explicit Prepare to repair. The 1.13-GB model is outside the Sherpa speech schema and its 1-GiB package bounds. Native transport uses canonical length-aware UTF-8; original source limits apply before inference-copy CRLF/CR-to-LF normalization. Decoding uses bounded adaptive context and rejects exhausted tokens/output instead of returning truncation.

Tencent uses deterministic strict UTF-8-prefix-constrained greedy selection, not unconstrained greedy: retain the ordinary maximum and tie ordering when eligible; otherwise select the highest-logit eligible token before commitment. Shared canonical parsing tracks request-local scalar state across exact length-delimited pieces, including split scalars and NUL. Reject impossible prefixes, overlongs, surrogates and values above U+10FFFF; permit EOS120020 only at a complete scalar boundary and no other control/EOG tokens. Reset state between independent calls and after abort. Keep strict final validation and explicit failure when no candidate is eligible. There is no output repair, byte dropping, replacement decoding, translation retry, fixture/language exception, sampling, prompt/model change or provider fallback. This Unicode constraint does not qualify language or meaning.


## Extension Invariants

1. **Compiled wiring:** Providers and adapter families are compiled into the application. Model metadata is data, not executable code. Do not add reflection-based plugins, downloaded code, or dynamic class loaders.
2. **Selected-only preparation:** Derive package/SDK resources from the selected configuration. Text-only startup must not scan speech packages or trigger speech downloads. Inference must not implicitly download missing models.
3. **Shared resources:** Reuse package references and deduplicate requirements. The evaluator's alternate tiny English ASR still consumes the retained tiny multilingual encoder/decoder packages; retiring standalone conversation language identification does not make those shared files obsolete.
4. **Owned lifecycle:** `AppRuntime` and `RuntimeOwnerController` serialize resource ownership. Use the existing `use`, `replace`, and `saveIfIdle` gate; await actual task/native lease teardown before constructing a successor. Preserve unchanged owners when configuration matches. Coroutine cancellation alone is not proof that JNI or SDK work has ended.
   Shared pair cutover awaits the current Conversation/Text ViewModel's real disposal before `AppRuntime.updateLanguagePair` commits under the owner gate using the latest advanced preferences. Backend Apply patches advanced fields onto the latest pair and awaits incompatible owner teardown BEFORE saving; compatible text owners are retained. `createConversationOwnerIfUnowned` checks ownership, persisted configuration and cancellation before any factory/close effects. Teardown failure blocks save/rebuild; failed save retains the old selection with safe idle recovery; failed postcommit open keeps the new persisted labels and reports a separate unavailable/restart state. Valid text-only pairs are intentionally ownerless and editable, not postcommit-open failure. No auto recording, preparation, retry, fallback or ownership theft. Advanced draft survives pair commit; Apply never restores its stale pair, Close cancels draft only, Reset preserves pair.
   Pipeline stop/clear and owner close barriers return cached `Result<Unit>` values, including failure, rather than failing the shared awaiter itself. Conversation/Text disposal shares an independently awaited `Deferred<Result<Unit>>`; each consumer explicitly consumes the result before save, replacement or further work. Synchronous Stop/background interruption revokes the session without letting a native stop exception escape the UI callback. Finalization still awaits capture/output/model/translation and other acquired leases after the first failure, retaining the original underlying error with distinct later failures. This is typed cleanup, not exception-message/class/stack heuristics, swallowed success, implicit retry or fallback; coroutine wrapper identity is not the SDK-error provenance contract.
   Guarded Text/Conversation construction checks the requested configuration against the latest persisted settings BEFORE validating eligibility; stale requests return without building or falsely classifying the newly selected text-only pair as a failed conversation open. The Conversation effect also reads the repository's latest state, rather than trusting a lifecycle-collected older snapshot. It checks freshness before owner effects and again after awaited disposal/refused creation; a non-teardown opening error is retained only for the still-current configuration. Genuine current-config open failures, teardown failures, no-retry policy and competing-owner protection remain distinct. A text-only selection stays ownerless with editable pair controls, not a sticky restart error.
5. **Bounded inputs:** Preserve strict catalog/settings parsing, safe relative paths, download/extraction quotas, bounded text/audio work, and bounded queues/UI state. Preserve current/previous-utterance presentation without turning the pipeline's historical transcript limits into a growing-feed UX.
6. **Honest availability:** Catalog metadata, successful installation, native compatibility, semantic quality, offline execution, and release/device qualification are distinct. Do not silently substitute a different language, voice, or engine when the selected combination is unavailable.

### Selected Recognition and Request-local Routing

`SpeechRecognitionBackend` persists only `system-offline` and `whisper`, with Whisper the fresh-install and Reset default. The old SHERPA conversation implementation and standalone LID model/adapter are removed; shared fixed-direction evaluator ASR remains. `ConversationRecognitionEngine` requires `readinessState`, `readiness()`, explicit `install()`, local-only `prepare()`, `recognize()` and awaited release. Typed states are READY, MISSING_LOCAL_MODEL, UNSUPPORTED, ENGINE_UNAVAILABLE, INCOMPATIBLE_SERVICE, SCHEDULED, DOWNLOADING, DOWNLOAD_FAILED and CHECK_FAILED; scheduled is not installed. The owner's model repository combines genuine native projection with its exact recognition instance. Checks and inference never download.

`SelectedSpeechResources.forConversation` receives explicit recognition model IDs:
empty for System and one shared ASR ID for Whisper. The projection may display
these rows but installs capture/output packages
only; the selected recognition engine owns its installation and readiness.

Whisper uses `WhisperConversationRecognitionEngine` and
`asr-whisper-small-multilingual-int8`. Its distinct `whisperMultilingual` adapter
does not relax the old monolingual `whisperOffline` contract. Three raw packages
share one definition across the current17 codes. One serialized resident owner
warms before publication and retains the native lease through actual return,
including cancelled/closed operations. The SDK cannot interrupt ORT; replacement
waits for stream disposal and close/join. One exact FloatArray is normalized
directly from immutable PCM without an intermediate ShortArray copy.

The native patch reads `whisper-language-pair` once, validates two distinct
metadata-backed codes before the encoder, compares only their SOT logits, and
reuses encoder cross-KV for one transcription. Equal scores choose the first
participant; no confidence threshold, separate classifier or second transcript
is used. Only native completion writes `whisper-language-pair-status=ok`.
Missing status, malformed candidates, wrong result language, native failure,
blank/oversize text and stale ownership cannot authorize direction/MT/output.
Generic stock stream-option roundtrip is not capability evidence: ordinary
builds require the source/patch/tool-bound custom AAR and retained native feature
marker. System-service controls are hidden, not cleared, for this choice.
Raw silence can produce a Whisper hallucination; production VAD is a required
input boundary rather than treating any low-level text as speech evidence.


Android requests are fresh per segment: PCM16 mono16k FD source, AUDIO_SOURCE segmented session, free-form, QUICK_RESPONSE, audio detection and both allowlists exactly the snapshot's two locales. Support uses the same shape with an operation-owned valid FD; online-only languages are not ready. Explicit installation requests only selected languages. Public re-entry/recheck obtains current support without polling or hidden retries.

Nullable `speechRecognitionService` is an Android component preference within System recognition, not another backend. Null retains `isOnDeviceRecognitionAvailable` / `createOnDeviceSpeechRecognizer`. An explicit component is discovered separately from admission and uses `createSpeechRecognizer(context, component)` without fallback. Admission requires an enabled/exported declared RecognitionService, exact Google component `com.google.android.tts/com.google.android.apps.speech.tts.googletts.service.GoogleTTSRecognitionService`, and exactly one current signer with SHA-256 `d22cc500299fb22873a01a010de1c82fbe4d061119b94814dd301dab50cb7678` or `7ce83c1b71f3d572fed04c8d40c5cb10ff75e6d87d9df6fbd53f0468c2905053`. There is no version allowlist; signing history alone and unknown current signers are not accepted. The same predicate governs installed status and public preparation, but admission does not establish language readiness. Installed-package absence is runtime unavailability, not settings corruption.

Only that qualified provider uses the narrow error14 compatibility rule: provisional14 may await a real installed-language inventory inside the original10s support budget; the first inventory is authoritative. Error14 alone remains CHECK_FAILED, other errors are terminal, and generic/default14 is not unsupported-language evidence. Both selected local languages must be installed, never merely online, supported or pending. Explicit Google requests set `PREFER_OFFLINE=true` for the inspected SODA route; this extra alone does not qualify arbitrary providers.

The user-approved trust model accepts authentic Google releases without checking a version allowlist and trusts the provider to honor the offline request. Language support/inventory is not a per-extra capability or no-network attestation. Runtime recognition errors, including error14, fail the current turn without translation/output or same-audio retry; only support-check error14 has the bounded inventory compatibility rule above. Future removal/change of the public installer action fails visibly without another destination. Historical binary inspection verified ARM64 210683481 and x86_64 210683483 signatures, four identical DEX files and equivalent service/installer declarations; their protobuf loader descriptor/native split differ by architecture and another protobuf embeds a different UUID. Those observations do not certify ARM/GrapheneOS runtime or future provider behavior.

An explicit audio session must match the identity that supplied its installed-language inventory, including package update time. Its writer waits for actual `onReadyForSpeech`, then rechecks identity and package generation before the first PCM write. Observed scoped system package events revoke readiness and pending/active requests, close FDs, cancel/destroy sessions and join writers before reuse. Background/disposal removes observation after existing cleanup barriers. These public SDK callbacks, PackageManager reads and broadcasts are not version-atomic remote-process attestation; the normal trusted-OS/package-manager race boundary is explicit, not silently replaced by a precheck guarantee.

Google recognition preparation uses a separate app-originated public `com.google.recognition.action.DOWNLOAD_LANGUAGE` activity with `android.speech.extra.LANGUAGE`. Attest current owner/configuration/identity and choose one missing selected locale under `owners.use`, then release the gate before external consent. Resolve within that package, require an enabled exported same-package activity, pin its component and recheck identity immediately before launch. Absence/denial is visible, with no alternate destination. Return only rechecks current inventory: no trusted resultCode, automatic recording, next-language launch or stalled Google `triggerModelDownload` call. The designated route retains native interactive-download callback semantics.


Terminal source resolution uses a bounded true-confidence mask, saturated selected weak histogram counts and terminal weak-run count, not transcript content, initial locale, previous language or callback-history storage. Only unique selected CONFIDENT/HIGHLY_CONFIDENT (2/3) is strong; successful switching never upgrades confidence. Conflicting/outside/unmapped/missing strong evidence fails. Without strong, require BOTH strict unique selected NOT_CONFIDENT histogram leader≥2 AND matching final consecutive weak run≥2; outside/unmapped tags block only weak-only conclusions and gaps reset the run. Failed/skipped switches and malformed metadata fail. Ordered primary final segments are assembled once, null/trim-empty contributions are ignored, alternatives are not concatenated, and empty final aggregate/over4096/overflow fails. Late callbacks cannot revive revoked requests.

One immutable PCM boundary copy feeds chunked unpaced FD writes; there is no appended silence, full second byte-array copy or second microphone. Segment maximum15s, recognize deadline30s and readiness/init10s bounds retain NonCancellable cancellation/FD/native writer release barriers. A failed turn keeps its error row and resumes listening without MT/output or a guessed language.

### Selected Speech Output and Truthful Timing

`SpeechOutputBackend` persists `system-offline` or `piper`; one backend implements `ConversationSpeechOutput.readiness(): SpeechOutputReadiness` (`READY`, `MISSING_LOCAL_VOICE`, `ENGINE_UNAVAILABLE`, `INITIALIZATION_FAILED`). System selected preparation excludes Piper TTS package download/digest/JNI load; Piper keeps its existing selected models, synthesis, AudioTrack and licensing obligations. System voice data is external engine-owned preparation, not a fabricated model-store package.

`AppSettings.speechOutputEnabled` is a live persisted choice, seeded into the owner/pipeline separately from structural `ConversationSessionConfig` identity. The same value governs ordinary validation, coverage, selected model preparation, readiness and startup; `ConversationModelRepository.install(speechOutputRequired)` and `isConversationReady(speechOutputRequired)` omit output-only packages during ordinary silent operation. After a failed supported-Piper enable, an explicit idle-only preparation action includes the missing selected output resources without changing the saved/effective choice. Fresh defaults and explicit Reset enable output; ordinary Apply, setup and pair changes patch the latest saved choice instead of replaying a stale settings draft.

Silent results complete as translated text without synthesis, playback, output-only capture pauses or a speech-presentation latency. Mute synchronously revokes an output generation, interrupts the real backend and cancels only the independent output child, not recognition, translation or the bounded utterance queue. Capture resumes only after that child and actual native/audio work settle. `ConversationSpeechOutput.throwIfReleaseFailed()` exposes retained release faults; cancellation must not turn failed audio/focus release into successful microphone reuse.

Enable first keeps the effective and saved choice off, checks the selected local capability and prepares output outside the long-held owner gate. A final current-owner/foreground/request-generation check and local attestation precede the narrow latest-value preference commit and enable. Only results completed after successful enable are eligible; old rows are never replayed. Unavailability is nonfatal to the silent conversation, with the actual reason and explicit idle-only recovery, no implicit download and no backend/voice substitution. Supported Piper data recovery uses the existing explicit Prepare action after Stop; it can install voices under existing download policy but never enables output itself. Failed output preparation retains usable silent readiness when base resources remain ready; later enable is a separate action. Failed persistence is visible; immediate mute is not undone just because its save failed.

The retained Route supplies both the live output choice and fresh capture state. The lower panel's noninteractive microphone indicator is not a translation-phase indicator: recognition/translation can run with capture active. Owner/pair/lifecycle transitions revoke stale capture indications. The speaker control has checked state, localized action/state and a long-press tooltip beside Start/Stop; provider attribution and independent transcript scrolling remain.

`AndroidTtsClient` checks current local inventory/data, excludes network and `KEY_FEATURE_NOT_INSTALLED` voices, and requires exact `setVoice` success/current-voice equality. The shared catalog locale mapping selects eligible voices; Mainland Simplified Chinese has the stricter country/script guard described above. There is no `setLanguage` network/default selection. Transaction-local native inventory avoids repeated lookup, not a cached readiness promise.

After all voice RPCs, one unique public `playSilentUtterance(0L, QUEUE_FLUSH, id)` attests the actual engine: capture `Binder.getCallingUid()` inline in matching Start/Done, resolve outside that callback to one installed registered TTS service package/application UID, and compare OS default/request as nomination only. Self/system-relay/shared/ambiguous/unexpected/missing identity fails closed. Android37 metadata RPCs may reconnect on error but do not replay the failed call: after attestation there are no more voice metadata RPCs before user speak, and user text errors are not retried across connections. There is no hidden SDK identity API/reflection or guessed-package compatibility fallback.

The no-audio control has a distinct ID/generation/waiter and never emits user phase/timing, focus, PCM or content logs. Initialization plus first voice/control check shares the existing10s bound; interruption/cancellation/close stops and completes pending work, invalidates identity and awaits actual release. Late callbacks cannot revive an owner; stop/shutdown failures remain sticky, failed identity requires explicit Recheck. User-triggered voice installation awaits fresh identity and checks current owner/config/foreground after await, then safely opens only that engine's exported data activity; absent handlers are an error, not a market/other-engine fallback.

`SpeechPlaybackStart.presentationTimeNanos: Long?` carries provenance: nonnull means first non-silent frame at the actual presentation boundary; `measured` distinguishes AudioTrack timestamp from observed-head-backed estimate. A phase-only platform `onStart` has null timestamp/false measured. The shared pipeline never derives a physical latency from callback/enqueue time, never carries a prior turn's value into that turn, and still preserves translation/completion. Details shows latency unavailable without number/threshold warning for phase-only turns; Piper retains its actual timestamp/head-backed display. This is not performance qualification.


## Practical Extension Recipes

Paths abbreviated with `...` below retain the module's existing `src/main/java/com/example/offlinetranslator/` package root.

### 1. Add a Text Language

1. Add canonical lowercase identity and `LanguageMetadata` to `core/src/main/java/com/example/offlinetranslator/core/LanguageCatalog.kt`, including a neutral source-language `warmUpText`. Add the corresponding `language_name_*` resource and `LanguageUiCatalog.languageName` mapping, translate it in every existing UI pack, and supply a complete new interface pack. Add the native UI locale to `app/src/main/res/xml/locale_config.xml` and its deliberate script mapping in `app/.../ui/InterfaceLanguage.kt` when necessary. The shared catalog drives the interface-language picker; do not add a second language catalog or assume speech tags are UI locales.
2. Check provider SDK support separately from translation method evidence. In `engine-mlkit/src/main/java/com/example/offlinetranslator/mlkit/MlKitTranslationEngine.kt`, `supportedLanguages` and `verifiedEnglishPartners` serve different purposes. Extend the latter only with actual directness evidence; it is not a semantic-quality certification. Preserve meaningful `Unknown` coverage (the existing SDK-supported `ja` fixture) and genuine unsupported-code coverage.
3. Apply the same executable-support rule at catalog, validator, registry and selected prepare/translate boundaries: accept SDK-supported Direct/Pivot/Unknown without changing method evidence, reject Unsupported before effects. Adding another text language does not change existing speech eligibility.
4. Update distinct contract/consumer tests for selected resources, genuine unsupported/error/cancellation and actual main-screen chooser/persistence/swap/recreation. Pair selection is immediate and shared; advanced Apply/Close/Reset never acts as a second pair source. Do not add source-copy or same-path language matrices.
5. Prepare only the selected real model online, then qualify both directions offline with everyday phrases and semantic controls for meaning, negation, names, numbers, and time. Record failures and uncertainty explicitly. Adding a catalog entry does not qualify the pair or add ASR/LID/TTS resources.

### 2. Add a Speech Model or Adapter

Backend assets retain schema version2: Sherpa owns `engine-sherpa/src/main/assets/speech-models.json` and runtime `sherpa-onnx-1.13.8`. Read common `SpeechModelCatalog.kt`, `SpeechModelDefinition.kt` and `SpeechModelAdapterReader.kt` in `speech-models/.../speechmodels/`, plus the backend loader/profile, before editing. Common parsing rejects unknown fields; the compiled decoder enforces backend role/family compatibility.

1. Add or reuse a `packages` entry. Existing fields are `id`, `displayName`, `source`, `license`, `url`, `allowedRedirectHosts`, `format`, `archiveBytes`, `archiveSha256`, `maxUnpackedBytes`, `files`, and optional `maxEntries`. IDs follow `[a-z0-9][a-z0-9.-]{0,79}`. URLs must be HTTPS with allowed redirect hosts; accepted formats are `raw` and `tar.bz2`.
2. Pin exact artifacts, archive sizes/SHA-256, extraction quotas, and a safe-path inventory of every expected file (`path`, `bytes`, `sha256`). Include license/attribution files where supplied. A license string or an upstream project's later relicensing announcement is not legal clearance for the pinned archive: check that exact code/weight package and its redistribution conditions. The current GigaAM archive metadata explicitly records its noncommercial-license caveat.
3. Add a `models` entry with `id`, `displayName`, `role`, `languages`, `sampleRateHz`, and `adapter`. Sample rate is model metadata, not a package field. Roles are `VAD`, `ASR`, `LANGUAGE_ID`, and `TTS`. VAD has an empty language list; other roles must satisfy family-specific language rules.
4. Reuse a compiled backend profile. Sherpa families include `silero`, `nemoCtcOffline`, `whisperOffline`, `whisperMultilingual`, `whisperLanguageId`, `piperVits`, `toneCtcOnline` and `zipformer2Online`. Legacy `nemoCtcOffline`/GigaAM is not the removed Parakeet backend. References use `{ "packageId": "...", "path": "..." }` and must resolve to declared inventory files or, for Piper `dataDir`, an inventoried directory. Match the family's exact parser fields and rate constraints rather than copying another family's JSON.
5. For a new Sherpa family, update sealed `SherpaSpeechModelAdapter`, `SherpaSpeechModelCatalog` and `SherpaModelFactories.kt` together, including role/rate checks and native teardown. A separate runtime owns a separate strict loader and compiled adapter implementing the shared marker; it must not relax the common parser or masquerade as a Sherpa profile. Factories create actual native configurations; metadata alone cannot implement a new engine. Wire a real provider through the existing runtime/pipeline ownership boundary.
6. Maintain host/evaluator projections and model-manifest checks where affected (`translator-test-kit`, `build-logic`, and `engine-sherpa-model-smoke`). Add package/parser/integrity and actual native model coverage, then qualify the selected conversation combination in both directions. A native decode smoke does not prove automatic language identification, semantic translation, usable voice, or phone performance.

Current parser bounds include a 256 KiB catalog, at most 64 packages and 64 models, at most 32 languages per model, at most 512 inventoried files per package, at most 1,024 extraction entries, and 1 GiB archive/unpacked limits. Only the per-model language ceiling changed from 16 to 32 for the 25-language model; unrelated settings/package/file limits are unchanged. Role-specific rates are narrower than the general 8,000–48,000 Hz model range. Preserve these checks; increasing a bound requires an explicit justified implementation change, not an oversized metadata entry.

### 3. Add a Translation Provider

1. Define a compiled `TranslationProviderDescriptor` with `id`, `displayName`, `provider`, `sdkVersion`, `attribution`, and `termsUrl`. This is a data descriptor, not a plugin interface.
2. Implement `core/.../core/TranslationEngine.kt`: the required `preparation` StateFlow, `modelAvailability()`, `prepare()`, `translate(pair, text)`, `close()`, and `closeAndJoin()`. Preparation is explicit; `translate()` must not download resources. Require valid selected pairs and nonblank bounded input, and preserve offline/resource behavior. Migrate every permanent test double and typed failure consumer together.
3. Update `app/.../runtime/TranslationEngineRegistry.kt` consistently: descriptors, ID/capability dispatch and the actual compiled factory. The registered ML Kit/Tencent implementations show both SDK and embedded-native ownership patterns; a descriptor alone is not a provider. Keep the one/two selected directed-pair bound and executable Unknown/genuine Unsupported distinction.
4. Report support/method evidence honestly and qualify quality separately. Settings schema7 writes closed fields `schemaVersion`, `languagePair` `{source,target}`, `speechRecognitionBackend`, nullable `speechRecognitionService`, `speechOutputBackend`, Boolean `speechOutputEnabled`, `translationEngineId`, `translationSetupComplete`, `vadModelId`, `vadMinSilenceMs`, `ttsSpeedPercent`, with known backend IDs only. The component string has bounded flattened-component syntax; a valid absent package remains a valid preference. Older schemas are intentionally unsupported in this development cutover; there is no migration or replacement-notification subsystem. Fresh defaults use RU→EN, Tencent, Whisper, System output and output enabled, but setup remains incomplete until an explicit first choice successfully persists. Engine selection and completion share one DataStore transaction. ## Installed Package Reuse and Lazy Migration

`SpeechModelStore` uses `noBackupFilesDir/speech-models`, with content-addressed directories `installed/<package-id>-<archiveSha256.take(16)>` and schema-2 pointers `active-package-<package-id>.txt` containing the directory name.

When a selected package's schema-2 pointer is absent, the store checks its fixed legacy seven-package pointer mapping under the store lock, verifies directory contents/hashes, and atomically creates the new pointer. A corrupt existing schema-2 pointer must not silently fall back to legacy metadata. Migration is per package, without a global version marker: unselected packages are not scanned, and valid byte directories are reused without copying or re-downloading. New model definitions should share existing package references where possible, rather than duplicating storage or introducing a global migration scan.

## Development Agent Skills

Agent skills are optional local development tools, not part of the source

are ignored by Git; their licenses and resources stay with those installations.
